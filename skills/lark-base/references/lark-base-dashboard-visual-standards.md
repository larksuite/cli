# 仪表盘布局与视觉规范

本文是规划仪表盘组件坐标的唯一依据：按专业 BI 仪表盘（Tableau、PowerBI、Google Data Studio 等）的排版规范，为盘上每个组件确定 `x/y/w/h`。仪表盘是 BI 系统的分析与呈现层，通过多种可视化组件将多个数据表或视图中的关键指标展示给用户。怎么调用命令（`+dashboard-block-list`、`+dashboard-block-create --position`、`+dashboard-layout`）见 [Dashboard 模块指引](lark-base-dashboard.md)。

**用户指令优先**：用户明确给出的坐标、行列数、尺寸比例、顺序具有最高权重，即使与本文的通用取值冲突。

**适用范围**：第 5 节的分栏要求、第 6 节的整盘约束（禁止空洞、水平铺满、末行铺满、垂直紧凑、底部齐平、面积校验）和第 8 节自检清单里的整盘项，只用于**新建看板、而且用户没有提布局要求**的场景；用户要求整盘重排或美化、又没给具体排法时，同样按新建处理。其他场景按下面的口径，不强制改成分栏，也不为了凑齐整盘约束去挪用户没让动的组件：

- **用户明确指定了位置、顺序、同一行等要求**：以用户要求为准，不强制分栏；用户没指定的部分再按本文规划。
- **在已有看板上追加组件**：不强制改成分栏。现有组件保持原坐标，新组件放进现有空位或接在现有组件下方，只为让新组件所在的行铺满而调整与它同行的组件。**盘面最底下是表格（`view` / `pivotTable`）时，新组件插在表格上方**，不要把新组件接在表格下面：优先把新组件并入表格上方的最后一行，按列基线收窄该行组件、让该行铺满；该行容不下时，新组件在表格上方单独占一行（占用表格原来的 `y`，表格整体下移），这一行只有它一个组件时可以占满 `w=48`。
- **定点修改（移动、调整大小、放进某个空位）**：只改目标组件的坐标，其他组件保持原坐标不动。目标组件移走后原位置会空出来，提交后兜底整理可能把下方组件上移补位，最终坐标以 `+dashboard-layout` 的输出为准。
- **无论哪种场景**，组件都不能互相重叠、不能越界（`x+w ≤ 48`），布局改动都要通过 `+dashboard-layout` 提交，不要绕开它逐个组件写坐标（例如逐个 `+dashboard-block-update --position`，或加 `--no-validate`）。

## 1. 坐标体系介绍

画布采用 **48 列固定宽度、无限高度** 的 Grid 栅格系统。每个组件用一个矩形区域表示，坐标定义为 `(x, y, w, h)`：

- **x**：组件左上角在水平方向上的起始列索引，取值范围 `[0, 48)`。
- **y**：组件左上角在垂直方向上的起始行索引，从 0 开始，无上限。
- **w**：组件占用的列数（宽度），`w > 0`，且 `x + w ≤ 48`。
- **h**：组件占用的行数（高度），`h > 0`。

整个画布由这些矩形拼接而成，横轴为列，纵轴为行。

## 2. 组件的位置关系

在布局中，我们关注组件之间的相对位置：

- **同行**：两个组件在垂直方向上有重叠或处于同一水平带（即它们的 y 区间存在交集）。
- **同列**：两个组件在水平方向上有重叠或处于同一垂直带（即它们的 x 区间存在交集）。
- **相邻**：两个组件在水平或垂直方向上边缘紧贴，中间无空隙。

这些关系用于指导组件分组、对齐以及视觉流的构建。

## 3. 画布的布局模式

为了构建清晰的信息结构，可采用两种基本布局模式，并可嵌套组合：

### 3.1 行列式

先整体划分成若干行，每行内再划分为若干列。组件在行内水平排列，行与行之间垂直堆叠。这种模式适用于结构简单、内容规整的仪表盘。

### 3.2 分栏式

有别于行列式，栏式布局先根据业务主题或功能将画布划分为若干个大的区块（每一块是个矩形区域），每个区块内部再采用分栏或行列式布局继续细分。分栏式能更好地体现信息层级，将相关组件聚合为视觉模块，提升可读性和组织性。

## 5. 组件的排布原则

整体布局应优先采用**分栏式（复合结构）**，后考虑行列式。经过设计的复合结构（纵向分栏 / 指标卡分组）是高质量布局的关键特征：它把相关组件聚成视觉模块，避免"从上到下一图一行"的平庸堆叠，也能防止组件因数量少而被拉伸过宽。

**什么才算分栏**：盘面上存在一个分栏区块——区块左右两侧各自纵向排列，且两侧的水平分界线**错开**、底部齐平。最典型的做法是一侧放一个主组件（主趋势图、排行榜、表格或 2×N 指标卡块），它的高度跨过另一侧纵向叠放的 **2 个及以上**较矮组件。下面两种看起来分成了左右两半，实际仍是行列式，**不算分栏**：

- 各行等高的 2×N 网格（每行两张同高的图）；
- 左右两栏各自叠放同样高度的组件（左右切开后每一层都对齐，等于逐行排列）。

**必须执行**（仅限开头「适用范围」里的新建场景）：盘上组件 ≥ 5 个（不计 `text`、`slicer`）时，必须至少安排一个分栏区块，不允许整盘只有行列式。组件 < 5 个时不强求分栏，按第 5.1 节排成整齐的行即可。盘上没有图表（只有指标卡，或只有指标卡和表格）时也不强求分栏：指标卡排成一行或 2×N 分组，表格整行置底。用户指定了排法、或在已有看板上追加和定点修改时，不适用这一条。

### 5.0 结构优先原则（务必先读）

成行平铺（1×N，把组件逐行铺满整行）只能得到规整但平庸的布局；具备设计感的布局来自**纵向分栏**或 **2×2 / 2×N 指标卡分组**等复合结构，这是普通布局与高质量布局的分界。

- 一旦第 5.1 节决策树命中复合条件，应采用复合结构，而非退回一图一行的平铺——平铺虽更易铺满，却难以形成清晰的视觉层级。
- 复合结构同样能满足第 6 节全部硬约束（无留白、无重叠、底部齐平）：第 5.2 节的对齐算法与骨架、第 5.4 节的示范均已保证这一点，无需为规避留白而牺牲结构。
- 在排布坐标前，先在设计阶段明确所选结构与依据（纵向分栏 / 复合 / 成行，及基于组件构成的判断），据此展开后续布局。

### 5.1 先按组件清单选结构（决策树）

先统计盘上各类组件数量：指标卡类（`statistics` / `progress` / `nps` / `countdown`）、图表类（柱 / 条 / 线 / 饼环 / 组合 / 雷达 / 漏斗 / 排行等）、表格类（`view` / `pivotTable`）、控件类（`slicer` / `text`）。然后按下述规则确定结构：

1. **指标卡 ≥ 4 个**：可排成一行，也可排成 2×N 分组（如 2×2、2×3），按盘面结构自行选择。指标卡必须集中在一处（顶部同一行，或侧栏的同一栏），不要拆散到盘面的不同位置。
2. **同时有指标卡和 ≥ 2 个图表**：优先 **纵向分栏**——左栏放指标卡 2×N 分组，右栏放一个主图，主图高度与左栏指标卡块齐平；或采用"顶部指标行 + 中部分栏区块 + 底部表格"的复合结构（中部分栏区块按骨架 B 安排）。
3. **图表 ≥ 3 个**：至少有一处用「1 个高的主图 + 旁边纵向叠 2 个矮图」的分栏区块，主图选最核心的趋势图或排行榜；不要把图表全部两两并排成等高的 2×N 网格。
4. **图表恰好 2 个**：两两并排（各 w≈24），不让单个图表独占整行满宽（表格 / 透视表除外）。
5. **表格 / 透视表**：置于最底部，可满宽 w=48。
6. **切片器**：置顶或置左，h=3；多个切片器排在同一行。
7. **文本**（只在用户要求把文字放进看板时才有）：按用途确定位置，h=3，不要把多个文本集中堆到顶部。
   - **整盘标题**：放第一行（`y=0`），位于切片器之上；单独占满 `w=48`，或与切片器同排拼满该行。
   - **分区副标题**：紧贴放在它所说明的区块正上方，宽度与该区块一致（区块满宽则 `w=48`）；区块内的组件全部排在副标题下方，直到下一个副标题为止。
   - **说明 / 解读文字**：放在相关组件所在区块的上方；判断不出归属时置顶，排在整盘标题之后。
8. **无分支明确命中 / 组件多而杂**（如图表 ≥ 6、或多类型混杂）：不要退回 1×N 平铺；先按业务主题或组件类型把画布切成 2~3 个区块（如「概览指标区 / 分析图表区 / 明细表格区」），每个区块内再套第 5.2 节的骨架与对齐算法继续细分。

### 5.2 分栏对齐算法与常用骨架

> 所有结构都必须满足第 6 节硬约束：无留白、无重叠、每行在 x 方向铺满 [0,48)、各栏底部齐平。下面的骨架只给出**结构安排**（各组件落在哪个栏、哪一行），坐标由对齐算法按实际组件数结算，而非套用一组固定数值——组件数不匹配时应重算，不应硬套。

**分栏对齐算法（保证底部齐平的通用方法）**

1. 选定分栏结构后，先为并列区块定一个共用总高 `H`（区块内各栏都结算到同一 `H`）。
2. 某栏内纵向堆叠 `k` 个组件时，令每个组件 `h = floor(H / k)`，再把余数 `H - floor(H/k) * k` 依次补到该栏最后一个组件上，使该栏各组件高度之和恰为 `H`。
3. 各栏都结算到同一 `H`，即天然底部齐平；栏宽在 x 方向拼满 [0,48)（如左 16 右 32，或左右各 24）。
4. `H` 以各栏组件的推荐尺寸高度为参考取合理值（指标卡分组区约 16，含图表的分析区约 28~36），确保结算出的每个 `h` 都落在其类型的推荐区间内。
5. 顶部指标行、底部表格行作为独立整行，各自 h 独立取值，不参与分栏区块的 `H` 结算。

**统一列基线（保证纵向对齐连贯）**

全盘尽量遵循**一套一致的列切分基线**，让纵向对齐线贯穿始终，各行列数保持克制统一，避免逐行在 1 栏 / 2 栏 / 3 栏 / 4 栏之间随意跳变，使结构连贯、层次清晰：

- 先按主结构选定一套列边界并全盘复用，例如 2 栏 `x∈[0,24)[24,48)`、或 3 栏 `x∈[0,16)[16,32)[32,48)`、或指标卡区的 4 等分 `12/12/12/12`；
- 相邻行的列切分点尽量对齐到同一组基线边界（如都在 x=24 处切分），而不是这一行切在 x=16、下一行切在 x=20；
- 整行组件（顶部指标行、底部表格）可跨基线满宽；分栏区块内的列边界应落在基线上。

**常用骨架（选定后用上面的算法结算坐标）**

- **骨架 A｜纵向分栏（左指标 / 右分析）** — 适用：指标卡为主 + 2~3 图表。左栏 x∈[0,16) 放指标卡 2×N 分组（可再叠 1 个图），右栏 x∈[16,48) 图表纵向堆叠；左右两栏用同一 `H` 对齐。
- **骨架 B｜顶部指标 + 中部分栏 + 底部表格** — 适用：指标卡 + 多图表 + 表格。首行指标卡铺满 [0,48)；中部是一个分栏区块：一侧放 1 个高的主图（如左 x∈[0,32)），另一侧纵向叠 2 个矮图（如右 x∈[32,48)），两侧用同一 `H` 结算，主图高度跨过两个矮图；末行表格整行 w=48。中部不要排成左右两列各叠等高图——那仍是行列式。
- **骨架 C｜少组件防拉伸** — 适用：组件 < 5 个、仅 2~3 图表、无表格。2 个图表时两两并排（各 w≈24）；3 个图表时用 1 个高的主图 + 旁边叠 2 个矮图，而非单图 w=48；含指标卡时先在顶部放指标卡（一行或 2×N 分组），再接图表。

### 5.3 避免单组件过度拉伸

- 单个非表格图表**不宜独占整行满宽**（w=48）；宽度优先控制在 w≤32，并与另一组件并排消化宽度。
- 各图表保持合理宽高比：比例类（饼 / 环 / 雷达）约 0.6~3.5，柱 / 条形约 0.5~4，折线 / 面积 / 组合约 1~5，避免压得过扁或拉得过宽。组件较少时用分栏 / 并排填满宽度，而非把单个图表拉满。

### 5.4 结构对照示范

先按组件构成选骨架（覆盖常见三类构成），再看下面的详例：

- **图表为主（图表 ≥ 3、指标卡 ≤ 1、无表格）**：选最核心的 1 张图做高的主图（如 w=32），旁边纵向叠 2 张矮图（如 w=16）构成分栏区块；剩余图表再两两并排。不要全部排成等高的 2×N 网格，任一图不占满 w=48。
- **指标卡为主（指标卡 ≥ 4、图表 ≤ 2）**：用骨架 A，指标卡在左栏 2×N 成块，右栏图表用对齐算法与左栏齐平；若无图表，指标卡排成一行或 2×N 铺满。
- **含表格（有 `view` / `pivotTable`）**：表格作为独立整行置底 w=48，其上方的指标卡与图表按骨架 A/B 分栏，表格不参与上方分栏区块的 `H` 结算。

下面的示例坐标以组件 id 为键，`type` 与 `name` 只用于对照组件类型；提交给 `+dashboard-layout --layout` 时，每项只需要 `block_id` 与 `x/y/w/h`（数组格式见 [Dashboard 模块指引](lark-base-dashboard.md)）。

下面以「4 指标卡 + 条形图 + 饼图 + 表格」的新建看板为例，两种排法组件完全相同，差别只在**是否采用复合结构**：

**反例（成行 1×N，几何合法，但新建看板组件 ≥ 5 时不允许）**

指标卡 (0,0,12,6) (12,0,12,6) (24,0,12,6) (36,0,12,6)；条形图 (0,6,24,16)；饼图 (24,6,24,16)；表格 (0,22,48,16)。
无留白无重叠、对齐也好，但组件逐行平铺、指标卡是 1×4 常规横排，盘面没有任何分栏区块。新建看板组件 ≥ 5 个时这种排法不符合第 5 节的要求，必须改成下面的分栏结构。

**正例（左指标 2×2 + 饼图 / 右主图，纵向分栏，表格置底）**

```json
{
  "s1": {"x": 0, "y": 0, "w": 8, "h": 6, "type": "statistics", "name": "累计销售额"},
  "s2": {"x": 8, "y": 0, "w": 8, "h": 6, "type": "statistics", "name": "订单数"},
  "s3": {"x": 0, "y": 6, "w": 8, "h": 6, "type": "statistics", "name": "客户数"},
  "s4": {"x": 8, "y": 6, "w": 8, "h": 6, "type": "statistics", "name": "客单价"},
  "c2": {"x": 0, "y": 12, "w": 16, "h": 12, "type": "pie", "name": "区域占比"},
  "c1": {"x": 16, "y": 0, "w": 32, "h": 24, "type": "bar", "name": "各区域销售额"},
  "t1": {"x": 0, "y": 24, "w": 48, "h": 16, "type": "view", "name": "订单明细"}
}
```

左栏（x∈[0,16)）4 指标卡 2×2 成块、下接饼图，右栏一张高的条形图跨过左栏三层；表格独占最底一整行。无留白、底部齐平（Y_max=40），具备清晰的纵向分栏，是典型的设计感布局。

下面给出一个完整的复合结构范例：

## 6. 硬约束

**禁止重叠**和**边界限制**在任何场景下都必须满足。其余整盘约束（禁止空洞、水平铺满、末行铺满、垂直紧凑、底部齐平、面积校验）在开头「适用范围」里的新建场景必须 100% 满足，确保画布被完全填满且无任何浪费；追加和定点修改时不为满足它们去挪用户没让动的组件。

- **禁止空洞**：所有组件必须完全覆盖 `[0, 48) × [0, Y_max)` 区域，其中 `Y_max = max(y + h)`。画布内不允许出现任何空白单元格。
- **禁止重叠**：任意两个组件的矩形区域不得有交集。
- **水平铺满**：任意 y 截面上的 x 投影必须填满 [0, 48)。
- **末行铺满（重点自查）**：最后一行同样必须在 x 方向填满 [0, 48)，末行组件右侧不得留有空白。只有表格 / 透视表可以独占满宽一行；若末行只剩单个非表格组件，不要把它拉满到 48，而是把它与上一行组件重排为同一行并排，或把它并入上方的分栏区块，使每一行（含最后一行）都恰好铺满。
- **垂直紧凑**：在任意列 x（从 0 到 47），该列上所有组件必须从 y=0 开始紧密堆叠，组件之间不得有垂直间距。
- **底部齐平**：所有列的最终底部边界必须统一对齐到 Y_max，不允许出现参差不齐的“锯齿底”。
- **面积校验**：所有组件面积之和必须等于画布总面积：`∑(w_i * h_i) = 48 * Y_max`。若不满足，需调整组件尺寸以达到完全填满。

**组件尺寸灵活性**：

- 组件尺寸可依据第 4 节组件列表，从其类型的推荐尺寸中取值。若未指定，默认 w ∈ [12, 36]，h ∈ [12, 24]。
- **同类组件高度一致**：并排的同一类型组件应尽量保持相同的高度，以增强视觉统一性；分栏区块里作为主组件的高图不受此限。
- **同类组件分组聚集**：相同类型的组件应尽量相邻放置，形成功能区块。
- **边界限制**：横向 `x + w ≤ 48`（任一 y 截面上的宽度之和等于 48 属于「水平铺满」，只在新建场景强制）。纵向画布可无限延伸，不限制最大高度。
- **具体类型高度约束**：
  - 指标卡：高度不应低于 5，建议优先使用 `h=6`，若与图表同行则取更大的高度以对齐。
  - 文本和切片器：高度统一设置为 3。
  - 其他图表类型（柱状图、折线图、饼图等）：高度不应低于 12。
  - 单个组件一般不要占满 48 宽度（表格和透视表除外）。

## 7. 最主要目标：美观度优化

在满足所有硬约束的前提下，必须主动应用以下美学原则来优化布局，以提升视觉吸引力和信息传达效率：

### 定性分析原则（指导布局结构与逻辑）

- **视觉流与扫描模式**：引导用户视线按 F 型或 Z 型路径浏览。核心指标放在左上角或顶部中央；通过组件大小和位置凸显重要性顺序。
- **信息层级与首屏核心**：构建“倒金字塔”结构，核心 KPI 指标卡位于首屏（y 坐标尽可能小），其次是关键趋势图，最后是明细数据。首屏应聚焦，避免过载。
- **认知负荷管理**：将相关组件分组邻近放置，形成视觉模块；模块间和组件内部通过微调间距保持适度留白（但必须在硬约束下，留白只能通过调整组件尺寸实现），降低拥挤感。
- **逻辑连贯性与一致性**：将切片器等交互控件置于顶部或左侧边栏，保持样式和排列一致，形成协调的视觉语言。

### 定量分析原则（指导几何调整与自检）

- **密度与展示**：在 100% 填满的硬约束下，通过控制单行组件数量或增大单个组件尺寸来降低信息密度，追求更好的展示友好度。
- **平衡与对称**：力求左右两侧视觉重量均衡，可通过将大型组件居中，或用相似尺寸的组件在左右侧呼应来实现近似的垂直对称。
- **简洁性与对齐**：最大化对齐线的复用，确保组件边缘在垂直和水平方向上严格对齐于网格，创造整洁、专业的视觉效果。
- **比例与均匀性**：避免组件出现极端瘦长或扁平形状，保持长宽比协调。同一模块内的组件尺寸和间距尽量统一，增强整体感。
- **重叠度**：绝对禁止任何组件间的非预期遮挡（已由硬约束保证），确保每个组件边界清晰可辨。
- **留白**：组件之间的垂直间距和水平间距（包括组件与画布边界的间距），必须满足硬约束。

## 8. 布局核心工作过程

为确保布局既符合专业美学原则，又严格满足硬约束，你必须按以下步骤依次执行，禁止跳过任意步骤：

### 1. 第一步：基于定性分析原则完成整体布局设计

- 优先确定核心布局模式（分栏式优先，行列式为辅），根据组件的业务主题、重要性划分功能区块，明确每个区块的核心功能；
- 规划视觉流路径（F 型 / Z 型），将核心 KPI 指标卡、关键趋势图表放置在左上角 / 顶部中央等视觉起点位置，构建 “倒金字塔” 信息层级；
- 确定各功能区块的边界范围（初步规划区块的 x/y/w/h），将同类组件、同业务主题组件归集到同一区块，降低用户认知负荷。

### 2. 第二步：几何调整（基于定量分析原则）

- 在整体布局框架下，为每个组件分配合适的尺寸（参考第 4 节组件列表的推荐尺寸）和精确坐标。
- 运用定量原则（密度、平衡、对齐、比例等）微调组件的位置和大小，使布局在视觉上更加均衡、对齐和协调。例如，对齐组件边缘，使同类组件高度一致，左右两侧视觉重量平衡。
- 此时，布局可能尚未完全满足硬约束，但应尽可能接近。

### 3. 第三步：自检与调整

提交坐标前，必须逐项核对以下清单，任一不通过就地修正后再提交。在已有看板上追加或定点修改时，只核对：无重叠、不越界、用户的要求已落实、新组件所在行铺满、表格仍在最底；其余整盘项只用于开头「适用范围」里的新建场景。

- **末行铺满**（最高优先）：最后一行的 x 投影是否填满 [0,48)？最后一个组件右侧是否留有大面积空白？若有，按第 6 节「末行铺满」规则把末组件与上一行重排并排（非表格组件不要拉满到 48）。
- **列基线一致**：各行的列切分是否遵循同一套列基线？纵向对齐线是否贯穿连贯、无逐行乱跳？若不齐，把列边界归拢到统一基线。
- **分栏区块**（新建看板、组件 ≥ 5 个且有图表时必查）：是否存在左右两侧水平分界线错开的区块（典型是一个组件的高度跨过旁边纵向叠放的 2 个及以上组件）？若整盘只有等高的行（含 2×N 网格），按骨架 A / B 重排。
- **指标卡集中**：指标卡是否都在同一处（顶部同一行或侧栏同一栏）？若被拆散到不同位置，归拢到一起。
- **文本位置**：整盘标题是否在第一行？每个分区副标题是否紧贴在它说明的区块正上方、且与区块同宽？若副标题被集中到顶部或与区块分离，移回对应区块上方。
- **无过度拉伸**：有无单个非表格图表独占满宽（w=48）或比例极端（过宽 / 过扁）？按第 5.3 节收进推荐区间并与邻并排。
- **其余硬约束**：无空洞、无重叠、水平铺满、垂直紧凑、底部齐平、面积校验（`∑(w_i*h_i)=48*Y_max`）。
- 若存在违规，在**不破坏整体布局结构和美学原则**的前提下微调 x/y/w/h（优先调宽 / 高，其次调位置）。
- 重复 “校验 - 修正” 流程，直至上述清单全部通过，再确定最终坐标。

## 9. 坐标的读取与提交

- 现有组件用 `+dashboard-block-list` 读取：每个组件返回 `block_id`、`type`、`name` 和 48 列 `position`，按第 5.1 节统计组件构成时以这里的 `type` 为准。
- 规划好的坐标：新建组件时用 `+dashboard-block-create --position` 带上；全部组件建完后，用 `+dashboard-layout --layout` 一次提交盘上全部组件的坐标。具体命令和参数见 [Dashboard 模块指引](lark-base-dashboard.md)。
