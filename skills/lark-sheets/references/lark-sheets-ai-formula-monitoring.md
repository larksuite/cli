# AI 公式结果监控

**标准模式使用 AI 公式前完整读取本 reference，按需 AI 真值分流**：原位回写或后续操作需要读取 AI 结果时，执行下述监控流程，并读取 `references/lark-sheets-formula-verify.md`。用户边界、保存和交付规则不变。

**需AI真值=否：铺完目标，首检通过即保留公式交付**。按以下顺序执行：

1. **铺完全部目标**：核对待写公式文本与引用后写入，不设等待出值的试点或探针。分批仅核对写入回执和入队状态，补齐失败或未完成项后继续，不等前批出值；pending 不阻止后续批次。完成其他不依赖 AI 结果的必要操作。
2. **首检全部目标范围**：用 `+formula-verify --ai-only` 查询。首检通过指查询成功、字段完整、目标覆盖可确认且目标范围无失败；pending 不要求归零。查询失败、缺字段或覆盖不明时排障，只重查受影响范围；确认 failed / unsupported 则按原因修复。补齐覆盖不是等待计算，不用汇总计数与预期格数作等值断言。
3. **通过即交付**：保留公式，按主 Skill 的渠道交付；仍 pending 时说明“公式已写入，仍在后台计算”，不声称业务结果已生成。无论是否出值，该区域均不再查状态、回读公式或结果、自检、抽检、试点或委派监控；其他区域的必要校验不重新开启本区域检查。样式、对象及源数据保护的必要核对在首检前完成。

本分支的 pending、等待时长或显示占位（含 `#ERROR`）不证明能力不可用，不触发通用失败降级。以下监控、读值和验收仅适用于需 AI 真值的区域。

## 主 Agent 写入和验收，子 Agent 只读监控

本文「主 Agent」指当前业务执行方（包括已接收整项业务委派的 Agent），负责写公式、读值验收、回写和交付；「子 Agent」仅指另行委派的只读监控者，不写表、不改公式、不生成替代答案。委派与等待能力由运行平台提供；实际不可用或明确禁止此分工时，记录限制，由业务执行方按下述规则监控。支持直接委派时直接交接监控阶段，否则由组织者转交阶段信息并汇总回执；不以监控委派重新分配整项业务。

1. **主 Agent 写入并确认回执**：按 `references/lark-sheets-formula-translation.md` 和 `references/lark-sheets-write-cells.md` 完成写入，核对种子格的 `formula` 文本，再用 `+formula-verify --ai-only` 首检本阶段全部写入范围。已有公式先定位并复用，不为监控重写。记录表 / sheet / 范围及本阶段输入、公式；输入或公式变更后，旧回执失效。
2. **需 AI 真值的阶段委派监控**：首检后即委派；交接上述定位、阶段信息、已有回执及本 reference。子 Agent 复核已有状态，已完成即返回，不人为等待；仍 pending 则持续监控，失败或状态不明按下表返回。不要先由主 Agent 多轮等待，也不以任务小或无并行工作跳过委派。
3. **使用真实任务与完成回执**：记录运行平台返回的任务标识；需要组织者转交时，按工具允许的参数传递阶段定位、已写公式与已有回执，以及本 reference 所在的技能目录；组织者再向监控子 Agent 明确同一范围和只读职责，不假定上下文自动继承。仅在回复中说“已委派”不等于创建任务。主 Agent 按运行平台要求等待或让出控制权，收到 `computed` 回执后按下节读值与校验，再执行后续操作和交付；期间只做不依赖结果、也不修改源数据、格址或计算区的工作；不因持续 pending 取消监控、改称能力不可用或生成静态替代答案。

## 子 Agent 持续查询到完成或出现实际问题

```bash
lark-cli sheets +formula-verify --url <表URL> --sheet-name <子表名> --range <本阶段全部公式范围> --ai-only
```

使用交接的阶段定位；token 定位时用 `--spreadsheet-token` 替代 `--url`，多范围逐一检查。字段和范围解释按 `references/lark-sheets-formula-verify.md`；不能假定 `--range` 收窄汇总，也不拿 `ai_formula_total` 与预期格数作等值比较。

| 状态 | 判据与动作 |
| --- | --- |
| 继续监控 | 查询成功、字段完整，按返回格址确认本阶段范围的覆盖及状态，目标范围内 `ai_formula_failed_count = 0` 且 `ai_formula_pending_count > 0`。使用运行平台等待能力，逐步增大查询间隔后维持稳定间隔；不循环读值、不重写公式。主 Agent、组织者和子 Agent 均不自行设置累计等待时限或轮数上限。 |
| `computed` | 查询成功、字段完整、目标覆盖可确认，且目标范围 pending = 0、failed = 0。只表示计算完成，不代表结果已验收。 |
| `failed` | 确认目标范围发生 failed / unsupported，附格址和实际错误交主 Agent 按原因修复。 |
| `blocked` | 查询报错（含限流、超时），或补读、拆分后仍缺字段 / 无法确认目标覆盖；附错误与最后已知状态交主 Agent 排障。未匹配目标或零计数本身不证明完成；纯 pending 不属于阻塞；查询 `error` 不等于公式 `failed`，不触发静态回退。排障恢复后继续原阶段。 |

回执包含任务标识、阶段、表 / sheet / 范围、状态、最后检查时间、实际计数、覆盖依据及错误原因。运行平台任务 `completed` 不等于公式 `computed`；主 Agent 核对阶段有效且公式状态为 `computed` 后才读值。用户取消、明确截止或运行平台强制中断时保留公式和最后状态，说明中断原因；不将其记为公式失败或生成静态答案。

## 主 Agent 读取所需结果并验收

读取本阶段全部结果，核对覆盖、行格映射、语言 / 标签 / 格式和业务边界，验收通过后再执行后续操作或交付。监控完成不代表业务校验通过。

原位回写、筛选汇总、导出真实值等操作所需的结果必须读全，确认可用及行格映射后再使用，不能用抽样替代业务输入。所读结果仍是计算占位、错误值或任务不允许的空值时，不算验收通过，也不据显示值认定公式失败：先按 `references/lark-sheets-formula-verify.md` 核对异步状态和公式文本；仍 pending 则继续监控，状态完成而值不可用则保留公式并排查读值链路。动态结果区继续保留公式。

## 同格编辑先在独立区计算，验收后回写

适用于已命中 AI 分流且用户授权的同格覆盖、同格双语、原位置翻译；原位回写属于需 AI 真值的后续操作，沿用上面的监控与验收流程。

1. 主 Agent 保存目标格的原值 / 原公式及行格映射，在不覆盖已有内容的独立计算区写入源值快照和引用快照的 `=AI(...)`，不引用即将被覆盖的原格。无在线 token 时仍按主 Skill 的导入和交付规则处理。
2. 监控期间不改原格。结果全部可读并完成当前模式要求的校验后，主 Agent 核对原格仍与快照一致；变动的格先重新读取并计算，不用旧结果覆盖新内容。同格双语由原文快照与 AI 译文按用户格式拼接，原文不再生成。
3. 主 Agent 按映射把上述 AI **值**写回授权原格，保留样式，核对写入回执；按当前模式要求回读目标范围。部分写入只补未成功部分。此回写是完成原位编辑，不是 pending 后生成替代答案。确认写入完成后只清理本次创建且不再被引用的临时区，不删除已有内容；动态结果区仍保留公式。
