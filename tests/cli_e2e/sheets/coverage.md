## Summary
- `TestSheets_BorderParameterDefaultsDryRun` and `TestBorderEmptySide*` cover empty side selection followed by weight/color refinement through standalone, multi-range, style-envelope, and batch-suboperation inputs. Empty final sides remain typed validation failures. Empty optional weight and `width` folding preserve the selected edges, values and formulas.
- `TestSheets_BorderAliasEmptyWeightDryRun` adds 36 command cases across `+cells-set-style`, `+cells-batch-set-style`, and the `+batch-update` style suboperation. It pins complete border objects for `border`/`borders`/per-side aliases with empty or whitespace weight, mixed styled sides, and independent color/weight; checks canonical attribute retention/merging; and rejects unfilled sides, nonobject canonical sides, conflicting attributes and null weight. Nearby `TestBorderEmptySideAliasCanonicalMergeRegression` and `TestBorderEmptySideAliasRejectsConflictsAndInvalidTypesRegression` cover merge, conflict and type boundaries; the existing `TestBorderEmptySide*` matrix now also runs both per-side alias spellings. All 36 cases and the complete Sheets `DryRun|Regression` suite pass locally. The same new test against the unchanged `975abae7` binary fails 15 cases across all three entries, detecting dropped selections and unfilled sides accepted as success. No new leaf commands are counted.
- `TestSheets_ResizeTypeAliasesDryRun` covers `+styles-put` and `+table-put` with `rows`, `ROWS`, `width`, and `px`, plus missing-size and wrong-axis rejection. `TestSheets_ResizeTypeAliasesWorkflow` reads exact row/column sizes after both writes.
- `TestSheets_CondFormatDefaultsBatchDryRun` and `TestSheets_CondFormatDefaultsBatchValidationDryRun` cover create/update for data bars, color scales and icon sets, including explicit style/null, rule-type precedence and malformed attrs. `TestSheets_CondFormatDefaultsWorkflow` creates and updates rules, checks their persisted identifiers/ranges/style/attrs, and checks calculated color-scale endpoint colors. Bar lengths and icon rendering have no documented result fields and are not asserted.
- `TestSheets_CondFormatOperatorDryRun` verifies that standalone create/update and their `+batch-update` suboperations retain `attrs[].operator` for all four `aboveAverage` operators. The cases cover rule type from the flag or properties, flag precedence, and comparison alias normalization for uppercase `cellIs` and `containsText` rule types in properties.
- `TestSheets_BorderParameterDefaultsWorkflow` compares omitted-weight and empty-weight results against separate canonical control cells, seeds visible borders before weight/color refinement, and checks untouched cell content and unselected edges. All three new live workflows create and clean up their own workbooks/folders. Local execution skipped with `config/not_configured`; live results must come from the MR CI before counting these workflows as verified.
- Its added `border_alias_empty_weight_Regression_writes_both_selected_sides` substep runs the exact `--style '{"border":{"left":{"weight":""},"right":{"style":"solid"}}}' --border-color '#123456'` combination through all three entries (21 border live cases total). Each reads back both left/right sides against canonical controls, asserts solid/thin and the requested color, and preserves distinct nonempty top/bottom sentinels and target/gap/control values. It reuses bot identity and parent-registered workbook/folder cleanup. This regression has not been run locally because real Lark configuration is unavailable; CI live is required. Backend line defaults and color assertions remain unchanged.
- CI evidence on `9b8e0817`: all 18 border cases, both resize carriers, and dataBar/iconSet create/update read-backs passed. The colorScale rule configuration passed, but its computed endpoint returned equivalent `rgba(255, 0, 0, 1)` instead of `#ff0000`; the color assertion now accepts exact opaque RGB equivalence. The complete live suite still needs a successful run on the final revision. Border expectations follow backend serialization: solid preserves all three weights; an omitted line style becomes solid/thin even if the request carries medium. Dry-run continues to require the exact requested weight, and nonempty unselected-edge snapshots must remain unchanged.
- TestSheets_FlagReconciliationDryRun: pins insertion's zero-based exclusive indexes, deletion's one-based inclusive indexes, batch deletion with start-index/count, explicit bold aliases taking precedence over a style envelope in both style commands, and agreeing formula inputs. Nested font and border envelopes normalize into canonical style fields; batch font sizes retain their numeric type. Conflicting formulas, conflicting axes, invalid insertion spans, unsupported font fields and overlapping font spellings produce typed failures before a request.
- TestSheets_DimShortcutsWorkflow reads back index-based insertion/deletion and verifies batch start-index/count deletion restores the original rows. TestSheets_CallCompatWorkflow reads back cleared bold styles for both aliases and both style commands, verifies nested font, alignment, wrap and border styles across five input carriers, then checks an agreed formula evaluates to 3. Both live flows create and clean up their own workbooks.
- Live fixture: a bot app with Drive folder creation, spreadsheet read/write, and resource deletion permissions (use the CI tenant credentials). Local execution was blocked during folder creation by `authorization/app_scope_not_applied`, reporting `drive:drive` and `space:folder:create`; no test workbook was created. Style checks read back `bold` before clearing it, then accept an explicit `normal` or the read API's omitted default `font_weight`; a no-op clear still fails. Dry-run tests pin the exact gateway method, URL, tool, body, and typed failures. Package tests compare standalone and batch dimension requests and check resolved `@file` formula inputs as substitute evidence when the live fixture is unavailable.
- TestSheets_CRUDE2EWorkflow: proves `+workbook-create`, `+workbook-info`, `+cells-set`, `+cells-get`, `+cells-search`, and `+workbook-export`; key `t.Run(...)` proof points are `create spreadsheet with +workbook-create as bot`, `read data with +cells-get as bot`, `find cells with +cells-search as bot`, and `export spreadsheet with +workbook-export as bot`. `+cells-search` asserts both halves — one match at `A2` for a term on the sheet, zero for one that is not — so a search that silently matched everything would still fail.
- TestSheets_CreateWorkflowAsUser_AATCompatible: proves the UAT path for `sheets +workbook-create` and `sheets +workbook-info` through `create spreadsheet with +workbook-create as user` and `get spreadsheet info with +workbook-info as user`.
- TestSheets_SpreadsheetsResource: proves direct `spreadsheets create`, `spreadsheets get`, and `spreadsheets patch`.
- TestSheets_FilterWorkflow: proves `spreadsheet.sheet.filters create`, `get`, `update`, and `delete`, with supporting sheet setup through `+workbook-create`, `+workbook-info`, and `+cells-set`.
- TestSheets_SheetShortcutsDryRun: proves request shapes for `+sheet-create`, `+sheet-copy`, `+sheet-delete`, `+sheet-rename`, and `+sheet-move` without hitting live APIs — all five reach the backend through `modify_workbook_structure`, so the pinned distinction is the `operation` and the fields packed beside it.
- TestSheets_SheetShortcutsWorkflow: proves live `+sheet-create`, `+sheet-copy`, `+sheet-rename`, `+sheet-hide`, `+dim-freeze`, and `+sheet-delete` flows against a real spreadsheet, verified by reading the workbook back through `+workbook-info` rather than by matching a field in each command's own response. Rename and hide answer with nothing but a revision counter, so the listing is the only place their effect can be observed (`sheet_name`, `is_hidden`); `+dim-freeze` reports `frozen_rows` / `frozen_columns` in its own result.
- TestSheets_ImageUploadDryRunParentType: dry-run coverage for the drive `parent_type` an image upload carries, across every surface a local file enters through — `+cells-set-image` and `+float-image-create`. A native spreadsheet must upload as `sheet_image` and one backed by an imported office file as `office_sheet_file`; a `/wiki/` ref must stay native, because a preview cannot resolve the node and so must not read the split out of the node_token. The negative half matters most: the backend does not validate `parent_node` against `parent_type`, so a wrong value uploads successfully and only surfaces later as an image that will not render.
- TestSheets_ImageUploadDryRunChunked: dry-run coverage for the 20 MB branch in `+cells-set-image`. Under the ceiling the preview shows one `upload_all`; one byte past it, the `upload_prepare` / `upload_part` / `upload_finish` trio Execute actually sends. Before that dispatch existed, an oversized image failed on `upload_all` with a bare `1061002` naming neither the size nor the limit.
- Cleanup note: workflow-created spreadsheets are cleaned up via `drive +delete --type sheet`; those cleanup-only executions are not counted as command coverage because no testcase asserts delete behavior as the primary proof surface.

- TestSheets_FindReplaceWorkflowAsUser_AATCompatible: ports the verified E2E find/replace scenario (source commit 68614d7d2106) to the existing harness; creates its own sheet, finds A2, replaces Alice with Alicia, reads back Alicia and unchanged Bob, and cleans up. The internal AAT job verifies the principal; the test name identifies the CLI user lane, not a claim of UAT identity.
