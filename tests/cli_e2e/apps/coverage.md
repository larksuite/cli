# Apps CLI E2E Coverage

## Metrics
- Denominator: 29 leaf commands in the selected apps E2E coverage set (not all 100 apps shortcuts)
- Selected command coverage: 100% (29/29)
- API dry-run coverage: 100% (27/27 API-backed commands)
- Local E2E coverage: 100% (2/2 local-only commands)
- Live coverage: file and role workflows are fixture-gated and skipped by default CI. File upload covers absolute-path upload, metadata readback, and cleanup; role workflows cover role lifecycle and member mutations with cleanup. Release creation has manual live evidence through same-ID terminal polling, but is not run in default CI because it triggers a deployment and has no rollback endpoint. Collaborator commands have manual live evidence for user, department, and chat collaborator CRUD, unpaginated listing, settings get/set, read-only errors, combined writes, readback, and rollback.

## Summary
- `TestAppsCreateDryRun`: happy path with `--app-type html`, all-fields shape, rejection paths (missing name, missing app-type, invalid app-type, legacy uppercase `HTML`). `--app-type` is a strict lowercase enum (`html`/`frontend`/`full_stack`); the CLI does not normalize case — legacy uppercase compatibility is a server concern.
- `TestAppsUpdateDryRun`: partial-field PATCH semantics; `--app-id` and at-least-one-field validation.
- `TestAppsDeleteDryRun`: two-step plan (GET the app to check `--confirm-name`, then DELETE the resolved `app_id`, nothing else); meta-token dry-run output marks the DELETE target as `<resolved_app_id>`; missing `--app-id` / `--confirm-name` and a blank `--confirm-name` are rejected with exit 2.
- `TestAppsListDryRun`: default `page_size=20`; empty `--page-token` omitted; negative size passed through to server (no client-side bound check); `--keyword`/`--ownership`/`--app-type` pass-through + empty-omission; invalid `--ownership` and legacy uppercase `--app-type` enum rejection.
- `TestAppsAccessScopeSetDryRun`: CLI input `specific`/`public`/`tenant` -> server enum `Range`/`All`/`Tenant`; `apply_config.approvers` shape; four mutex rejection paths.
- `TestAppsAccessScopeGetDryRun`: URL shape; no body/params on GET; `--app-id` required.
- `TestAppsReleaseCreateDryRun`: POST path contract; an optional supplied `apply_reason` is forwarded verbatim and omitted for the HTML-compatible flow; optional `branch` is trimmed and omitted when absent; explicit blank reasons, dangerous Unicode, and the 1000-code-point boundary are pinned before any request plan is emitted.
- `TestAppsHTMLPublishDryRun`: walker manifest for directory + single file; hidden files intentionally included (design decision); empty dir / missing `index.html` produce envelope `validation_error` field (dry-run exits 0 advisory, not blocking); both required-flag rejections.
- `TestAppsFileUploadDryRun_AcceptsAbsoluteHostPath`: dry-run validates an absolute local file and derives its basename without uploading it; a missing source path is rejected before preview.
- `TestAppsFileUploadLiveWorkflow`: fixture-gated absolute-path upload, `+file-get` readback, and `+file-delete` cleanup in a dedicated app.
- `TestAppsFileAppIDStatesDryRun` / `TestAppsFileAppIDNotFoundLive` / `TestAppsFileNoPermissionLive`: keep three states that once shared one error apart. A `--app-id` that was never an app id (meta token, page token, bare numeric id) is rejected in `Validate` with exit 2 and a hint naming `+get`, so the dry-run half needs no backend; a well-formed but unassigned app id is syntactically fine and can only be judged live, where the assertion is deliberately negative — it must not come back as `authorization` / exit 3, which would send a caller to request access that cannot help. A real app in the same call shape must still succeed, so the case cannot pass by rejecting everything. The third case is the mirror: an app the caller has no role on (`LARK_CLI_E2E_APPS_NO_PERMISSION_APP_ID`) must keep reporting `permission_denied` / exit 3, so an over-correction cannot sweep a genuine permission failure into `not_found`.
- `TestAppsFileDownloadURLRoundTripLive`: fixture-gated round trip proving a platform-issued `download_url` is accepted wherever a `--path` is taken. Uploads a file, reads its `download_url` back (rather than constructing one), and feeds it to `+file-get`, `+file-sign` and `+file-download`, asserting each resolves to the real `path` and that the downloaded bytes match. A negative case keeps the compatibility from degrading into "accept anything": an absent file must still fail `not_found` in both the plain-path and `download_url` shapes. Resolution happens server-side — the CLI forwards `--path` verbatim — so only a live call can catch a regression.
- `TestAppsGitCredentialInitDryRun`: URL shape for issuing an app Git PAT; no body; `app_id` query metadata included.
- `TestAppsGitCredentialListLocalE2E`: local-only command scans every app storage directory and reports repository URL and status without exposing PAT or expiry details.
- `TestAppsGitCredentialRemoveLocalE2E`: local cleanup command removes app-scoped metadata under an isolated config dir.
- `TestAppsRoleManagementDryRun_RequestShapes`: role CRUD/member/match request shapes for all 9 role shortcuts. Request/response fields follow the API contract: `name`, `role_id`, `users`, `departments`, `chats`, `target_user_id`, and `roles`.
- `TestAppsRoleManagementValidation`: deterministic typed validation for invalid role ID, page bounds/token, missing update fields, missing member input, `--all` conflicts, and missing `--user-id`.
- `TestAppsRoleManagementLiveWorkflow`: fixture-gated live role/member workflow against the role provided by `LARK_CLI_E2E_APPS_ROLE_ID`. It refuses to run when the selected member already exists, mutates only that member, and removes only that member during cleanup; it never changes a shared role definition or clears unrelated members.
- `TestAppsRoleLifecycleLiveWorkflow`: creates a uniquely named transient role, independently reads it back, updates and re-reads it, adds a fixture member, clears all members and proves the role still exists, then deletes it and verifies the target `role_id` is absent. Cleanup is armed before creation and uses only environment-provided test identifiers.
- `TestAppsRoleMatchListLiveWorkflow`: separately fixture-gated live `+role-match-list` proof against the same isolated fixture role. It also requires the selected user to be absent at baseline and removes only the user it added.
- `TestAppsMemberDryRun`: request shapes for all six Creative collaborator commands, including typed external ID projection (`openid` -> `user_open_id`, `openchat` -> `chat_id`, `opendepartmentid` -> `department_id`), filters, unpaginated member lists, and partial settings PATCH semantics.
- `TestAppsMemberHighRiskWritesRequireYesButDryRunDoesNot`: all four collaborator/settings writes require explicit confirmation for live execution while remaining directly inspectable with `--dry-run`.
- `TestAppsMemberValidationFailuresAreStructured`: deterministic validation envelopes for mismatched typed IDs, invalid settings enums, and empty settings updates.
- `TestAppsMemberUnsupportedWriteFlagsAreNotRegistered`: `external_invite` and `copy_download_by` remain readable, while their unsupported setter flags are absent from the real CLI command and rejected as unknown flags.
- `TestAppsExportContentTypeE2E`: response-handling proof for `+export` against a local CONNECT-terminating HTTPS gateway. An archive served as `application/x-zip-compressed`, `binary/octet-stream`, `application/force-download`, or with no Content-Type reaches disk byte-for-byte; a `application/json` or `application/problem+json` error envelope fails the command, writes no file, and surfaces the server's reason. Dry-run cannot cover this: the request is identical across all six cases and only the response differs.
- `TestAppsFileRemotePathDryRun`: every storage command that takes a remote `--path` (`+file-get`, `+file-sign`, `+file-download`, `+file-delete`, `+file-list`) rejects a Windows drive path — what Git Bash (MSYS) turns `/1858537546760216.png` into before lark-cli runs — in `Validate` with exit 2, `--path` as the param and a hint naming `MSYS_NO_PATHCONV=1`; the plain remote path still reaches the request plan verbatim.
- `TestAppsReleaseGetDryRun`: a numeric `--release-id` plans `GET /apps/{app_id}/releases/{release_id}`; values the gateway cannot accept as a 64-bit integer (a placeholder, a quoted id, a digit string past the int64 range) are rejected in `Validate` with exit 2 and a hint naming `+release-list`.

Blocked: General app create live E2E is intentionally not implemented yet. Apps shortcuts are user-only, and `+delete` can return trash, permanent-delete, or unspecified results depending on the server response, so it is not a deterministic cleanup primitive for create-and-cleanup tests. Release-create live E2E is also intentionally manual: it starts a deployment (and may start approval), while the CLI has no deterministic rollback/cancel endpoint for cleanup. File upload and selected role live workflows remain fixture-gated; each uses dedicated fixtures and cleans up the resources it mutates. Collaborator live coverage is currently manual rather than default-CI automation because its write cases require isolated user, department, and chat fixtures; the live contract and cleanup workflows have been exercised end to end.
